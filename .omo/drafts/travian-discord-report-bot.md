## Decisions ledger

- **Storage**: bot-owned SQLite file on a Docker volume (snapshots + computed deltas). Friend's DB READ-ONLY (backfill/baseline). No writes to friend's DB.
- **Fetch schedule**: daily 00:15 server time (Europe/London; margin over 00:00 + 5-20s availability). Configurable FETCH_HOUR/FETCH_TZ.
- **Report time**: default 09:00 Europe/Warsaw, configurable REPORT_HOUR/REPORT_TZ.
- **Alliance tracking**: env ALLIANCE_TAGS (comma-separated tags) — no hardcoding.
- **No map, no images (user decision, 2026-08-09, round 3)**: reports are TEXT ONLY. No own web map app, no fragment PNG, no links to friend's map. Regions shown as a text table in the embed (region, our villages, our pop, share %, delta). Dropping the map also removes Cloudflare Tunnel/domain hosting from scope.
- **Region status limitation**: map.sql has per-village region + pop, but NOT official locked/contested/secured status (in-game statistics need login) — report computes our pop share per region + top-5 alliances per region instead. State this in plan.
- **Test strategy**: TDD for parser + metrics engine (pytest); agent-executed QA for bot glue and deployment.
- **Local config dashboard (user idea, 2026-08-09, round 4)**: FastAPI app in the SAME image, second compose service `dashboard`, bind 127.0.0.1 (not exposed; no auth by default, optional token env if bound to LAN later). Defaults: status page (latest snapshot date, village/player/alliance counts, next fetch/report time), settings editor (ALLIANCE_TAGS, REPORT_HOUR/REPORT_TZ, FETCH_HOUR/FETCH_TZ, CHANNEL_ID) persisted to `settings` KV table in shared SQLite (env = default fallback; DISCORD_TOKEN stays env-only), action buttons (Fetch now / Send report now), last-run errors. Shared internal trigger function used by all surfaces.
- **Manual report trigger (round 4)**: Discord slash command `/raport` restricted to admins (permission check: manage_guild or dedicated role via env) + dashboard button "Send report now"; both call the same internal trigger function; useful for testing.
- **No own map**: reports link to friend's map site; optional later: friend adds ?x=&y= deep-link (their repo, out of our scope).
- **Test strategy**: TDD for parser + metrics core; agent-executed QA for bot glue & deployment. (to confirm in brief)
- **Deployment defaults**: private GitHub repo, GHCR image, GitHub Actions build+push on tag/main, docker-compose.yml + .env on server, update script `./update.sh` (pull+up -d); optional watchtower (not default).

## Approach (to plan)

Monorepo (Python 3.12, uv, pydantic v2, ruff, basedpyright, pytest):
- `travian/` shared lib: typed models (Village/Player/Alliance/Region), map.sql parser (escaping: SQL quotes, HTML entities, unicode), SQLite snapshot store (snapshot per `_date`), metrics engine (deltas: villages/pop/players/VP; regions; top players).
- `bot/`: discord.py bot — APScheduler: fetch 00:15 Europe/London (map.sql, margin over midnight availability) + parse + store; report 09:00 Europe/Warsaw: EN text embed; blocks: summary+deltas, gained/lost villages, top players, regions table, VP.
- Docker: Dockerfile (python:3.12-alpine); one GHCR image; docker-compose.yml services: `bot` (entrypoint bot) + `dashboard` (entrypoint uvicorn, port 127.0.0.1:8090), shared volume for SQLite; .env (DISCORD_TOKEN, CHANNEL_ID, ALLIANCE_TAGS, REPORT_HOUR/REPORT_TZ, FETCH_HOUR/FETCH_TZ).
- Backfill (optional, config-gated): read friend's Supabase Postgres (pooler, read-only) for pre-bot history; graceful skip if unreachable.
- GitHub: private repo, Actions build+push images on push to main; update script `./update.sh` (pull + up -d) on server.
